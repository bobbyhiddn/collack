# Comprehension-first three-fight run

This is the deliberately small proof slice implemented by
`battle/short_run.lua`. It does not expand the campaign to five or seven
fights. The shipped client opts into this mode explicitly; the earlier
single-battle draft fixture remains available to its existing headless
contracts.

## Run spine

The run starts in visible setup with Momentum, Chalk Pebble, Quartz Round,
and three bricks: Basalt Absorber, Granite Fortifier, and Mirror Pane. The bag
is ordered, but the formation starts empty so the player must place each
brick. The collection may contain at most four marbles and six bricks.

The fixed route is:

1. Switchback Scout: Ricochet, two marbles, and a sparse mirror/fuse pair.
2. Fuse Garden: Effect Amplifier, three marbles, and four status/release
   bricks.
3. Brass Bastion: Momentum, four marbles, and five
   guard/sustain/burst bricks.

Each setup exposes the next opponent's counts, scout tags, formation, bag,
and canonical generated rule copy before the automatic battle. A loss or
draw ends the run immediately. A third victory ends it with
`three_fights_cleared`.

## Refit and attrition

Victories in fights one and two produce one seeded offer of exactly three
legal choices. A choice is a typed operation: add, replace, repair, remove,
or reshape. Its card carries both generated operation copy and the selected
item's grammar-generated compact and expanded mechanics. Causal attribution
records the operation, target, source RuleSet, source rules, and both generated
copies.

Destroyed bricks leave the active formation and persist in the workshop as
exact repair candidates. Surviving bricks return at full integrity for the
next fight. Reward application preserves the ordered bag and existing
formation cells where applicable, never exceeds the four-marble/six-brick
caps, and returns to setup before the next battle.

## Canonical and deterministic boundaries

All player and opponent content is constructed from the 17-item comprehension
pool documented in [`rules-grammar-core.md`](rules-grammar-core.md). Every
attributed combat event is projected into the run's causal ledger with a
callout generated by `battle/rule_ast.lua`; no separate mechanics prose
defines behavior.

Battle and refit domains derive stable per-fight seeds from the run seed.
Boundary saves are supported during setup, refit, and terminal result, but not
while the mutable battle engine is stepping. A terminal record contains the
semantic command journal, all three immutable battle recordings, checkpoint
hashes, casualties, choices, and causal ledgers. Same-build replay reconstructs
the run from those semantic commands and recordings and rejects altered or
version-mismatched data.

Touch and mouse use the same semantic action IDs throughout setup, refit,
battle inspection, settings, replay, and new-run navigation. Mute and reduced
motion remain view/runtime settings and do not enter deterministic run state.
